## CRE Acquisitions Platform — Stage 1 OM Screener

### Build Status: Days 1–3 **COMPLETE & SHIPPED TO TESTED**

The ingestion layer (input discovery, Excel parsing, PDF extraction, OCR detection, OCR processing) was finished yesterday. Today focused on the merge layer: combining parsed Excel data with Claude-extracted OM metrics into a unified data structure.

### Day 3 Build: Merge Layer

**Files Created:**
- `prompts/om-extractor.md` — disciplined extraction prompt for OM text. No inference. Returns null when data is missing or ambiguous. Designed to feed directly into the extraction metrics schema.
- `src/merge_inputs.py` — implements the core merge logic: Excel data wins field-by-field, Claude extraction fills remaining nulls, every field carries a source tag (excel, claude, null) for human review traceability.
- `src/normalize_excel_output.py` — translation layer mapping the flat Excel parse output (from parse_excel.py) into the nested ExtractedMetrics schema. Ensures downstream code sees a consistent nested structure.
- `tests/test_merge.py` — 23 unit tests covering edge cases: missing files, partial data, field priority rules, source tagging, schema validation. All passing.

**Key Design Decisions:**
1. **Field-level merge rule:** Excel always wins when present. Not document-level precedence, but per-field. This respects that Excel may have clean Unit Count but PDF has better debt details.
2. **No inference in extraction:** The OM extraction prompt enforces that null is the correct answer when data is absent, ambiguous, or would require interpretation. Extraction flags document *why* data is missing (not found, unclear, construction phase, etc.), so human review gate can decide how to handle it.
3. **Source tracking:** Every metric carries a source tag so Will can see which document contributed which value. Builds trust and allows quick human correction if sources are wrong.
